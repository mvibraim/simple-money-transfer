## The build is red out of the box

`./gradlew test` currently fails, and it is *not* something you broke:

```
DataSourceProperties$DataSourceBeanCreationException
```

`spring-boot-starter-data-jpa` is on the classpath, but `application.properties` sets only `spring.application.name` and there is no embedded database dependency. Any `@SpringBootTest` will fail to start a context until a datasource exists. Before writing feature code, resolve this deliberately — add a runtime database (e.g. H2 as `runtimeOnly`/`testRuntimeOnly`, or Testcontainers), or drop the JPA starter if persistence isn't wanted. Don't work around it by weakening tests to avoid loading the context.

## Spring Boot 4.1 dependency conventions

The version matters here: **Boot 4.1.0 on Spring Framework 7**, Java 25 toolchain, Gradle 9.5.1. Boot 4 split the old monolithic starters, so names carried over from Boot 3 habits or older docs will not resolve:

- Web is `spring-boot-starter-webmvc`, **not** `spring-boot-starter-web`.
- There is no single `spring-boot-starter-test`. Test support is per-module and mirrors each production starter: `spring-boot-starter-webmvc-test`, `spring-boot-starter-data-jpa-test`, `spring-boot-starter-validation-test`. **Adding a production starter means adding its matching `-test` sibling**, otherwise that module's test slice annotations and helpers are missing.

JUnit 5 (Jupiter, on JUnit Platform 6), Mockito, AssertJ, and `spring-test` all arrive transitively through those `-test` starters — declare them explicitly only when you need a version the BOM doesn't supply.

Versions come from the `io.spring.dependency-management` BOM, so add dependencies without version numbers.
