# F01 — H2 foundation (green build)

**Branch:** `feat/01-h2-foundation` · **Depends on:** F00

## Goal

Turn the build from red to green by giving the JPA starter an actual
database — for tests, an in-memory one. Nothing domain-specific happens
here; this is the scaffolding every later feature builds on, and it
introduces the H2/Mockito testing strategy from day one.

## Scope

- `build.gradle`: add `implementation 'org.springframework.boot:spring-boot-starter-flyway'`,
  `runtimeOnly 'org.postgresql:postgresql'`,
  `runtimeOnly 'org.flywaydb:flyway-database-postgresql'` (the production
  path), and `testRuntimeOnly 'com.h2database:h2'`,
  `testImplementation 'org.springframework.boot:spring-boot-starter-flyway-test'`
  (the test path). All versions come from the Boot BOM — no version
  numbers declared. Mockito arrives transitively through the existing
  `-test` starters; no separate declaration needed.
- `src/main/resources/application.yaml` (replaces `application.properties`):
  `spring.jpa.hibernate.ddl-auto=validate`, `spring.jpa.open-in-view=false`,
  `spring.flyway.clean-disabled=true`. No datasource URL yet — that
  arrives with the real Postgres connection info in F02.
- `src/test/resources/application.yaml` — a complete test-scope override
  (Gradle puts test resources ahead of main resources on the classpath, so
  this file fully replaces the main one for tests, not merges with it):
  `spring.datasource.url=jdbc:h2:mem:money;MODE=PostgreSQL;DB_CLOSE_DELAY=-1`,
  plus the same `ddl-auto`/`open-in-view`/`flyway.clean-disabled` settings.
  **`DB_CLOSE_DELAY=-1` is required** — without it H2 drops the in-memory
  database the moment the first connection closes, breaking any test that
  opens more than one connection.
- `src/test/java/.../support/AbstractIntegrationTest.java` — `@SpringBootTest`
  base class, tagged `@Tag("integration")`.
- Retarget `SimpleMoneyTransfersApplicationTests` to extend that base.
- Gradle `test` task reads a project property to exclude the `integration`
  tag: `./gradlew test -PexcludeTags=integration` runs the fast,
  Spring-context-free unit loop.

## Explicitly not in this feature

- No dev-convenience compose file for a real local Postgres (F02).
- No domain tables, entities, or Flyway migrations (F06+) — Flyway starts
  with zero migration files and just creates its history table.
- No Testcontainers, anywhere, ever (see F00's testing-strategy section
  for why).

## Design notes

- **Why H2 over Testcontainers.** The original design used Testcontainers
  against real Postgres. That is blocked on the reference development
  machine by a Docker Engine 29.7.2 / docker-java incompatibility (see
  F00). Switching entirely to H2 for tests sidesteps it and, as a side
  effect, makes the whole suite fast and Docker-independent — a
  deliberate trade against losing Postgres-specific test coverage,
  documented in F00 rather than hidden.
- **`MODE=PostgreSQL`** narrows the gap but does not close it: H2 still
  has no PL/pgSQL, different locking semantics, and a few syntax
  differences (`~` vs `REGEXP_LIKE`, `BIGSERIAL` vs
  `GENERATED BY DEFAULT AS IDENTITY`). The portable-DDL rules in F00 exist
  to keep shared migrations inside the subset both engines accept.
- `ddl-auto: validate` is chosen over `update` deliberately — schema is
  owned by Flyway migrations from F06 onward; Hibernate only checks that
  mapped entities agree with what's already there.
- Flyway is added now, before a single migration exists, so the
  `flyway_schema_history` table and validate-on-migrate behavior are
  exercised from the first commit rather than introduced as a surprise
  later.

## Verification

```bash
./gradlew test -PexcludeTags=integration   # fast, no Spring context
./gradlew test                             # full suite, H2 in-memory — no Docker needed
```

## Review focus

- No version numbers anywhere in the new `build.gradle` lines — the BOM
  should be the only source of truth.
- The test-scope `application.yaml` is a full override, not a merge —
  confirm it repeats every setting a test actually needs rather than
  assuming it inherits from the main file.
- `AbstractIntegrationTest` is the only base class integration tests
  extend from here on.
